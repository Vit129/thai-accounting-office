# Thai Accounting Office

Plugin สำหรับ Claude (Claude Desktop / Claude Code) ที่ทำหน้าที่เสมือน "หัวหน้าฝ่ายประสานงาน" ของสำนักงานบัญชี:
**คุณเป็นหัวหน้าที่สั่งงานและตัดสินใจ** Claude อ่านอีเมลและเอกสาร ลงบัญชีใน Excel / Google Sheets
ปิดงวด เตรียมภาษี ตรวจตัวเลขก่อนส่งทุกครั้ง แล้วมารายงาน และมีสามอย่างที่ทำให้มันดีขึ้นเรื่อยๆ:

1. **จำถาวร** — ทุกงานที่ทำเสร็จหรือติดปัญหา Claude จดลงสมุดบันทึกงาน: ใช้ไฟล์ไหน ชีทไหน ช่วงเซลล์ไหน
   เมลหัวข้ออะไร ใช้สูตรอะไร ตรวจอะไรผ่านบ้าง เจอปัญหาอะไร ย้อนถามได้ภายหลัง ("ตัวเลขนี้มาจากไหน")
2. **เก่งขึ้นเองทุกงาน** — ทุก skill อ่านบทเรียนก่อนทำ และเรียนรู้จากทุกครั้งที่คุณแก้หรือตรวจไม่ผ่าน
3. **ข้อมูลอยู่ในโฟลเดอร์ของคุณ** — ความจำทั้งหมดอยู่ในโฟลเดอร์งาน (`Accountant/`) ไม่ถูกเขียนลงใน plugin

## การติดตั้ง (Installation)

### ใช้งานบน Claude Desktop:
1. ดาวน์โหลดไฟล์ `thai-accounting-office.zip` จากหน้า [Releases ล่าสุด](https://github.com/Vit129/thai-accounting-office/releases/latest)
2. เปิด **Claude Desktop** ไปที่ **Customize → Plugins → Add → Upload plugin** แล้วเลือกไฟล์ `thai-accounting-office.zip`
3. **สร้างโฟลเดอร์งาน:** สร้างโฟลเดอร์สำหรับเอกสารบัญชี เช่น `Accounting/` (แนะนำพาธสั้น ๆ บน Google Drive หรือ OneDrive)
4. คัดลอกไฟล์ [`work-folder-CLAUDE.md`](../skills/company-profile/references/work-folder-CLAUDE.md) ไปวางไว้ในโฟลเดอร์งาน แล้วเปลี่ยนชื่อเป็น `CLAUDE.md` (`CLAUDE.md` ที่ root ของ repo เป็นโน้ตสำหรับคนดูแล plugin ไม่ใช่ไฟล์นี้)
5. เปิดแชทในโฟลเดอร์งาน แล้วพิมพ์ **`เริ่มงาน`** เพื่อเริ่มต้นตั้งค่าข้อมูลบริษัทครั้งแรก

### ใช้งานบน Claude Code (อัปเดตอัตโนมัติ):
1. `/plugin marketplace add Vit129/thai-accounting-office`
2. `/plugin install thai-accounting-office@thai-accounting-office`
3. เปิด auto-update ของ marketplace นี้ในเมนู `/plugin` → Marketplaces เวอร์ชันใหม่จะเข้ามาเองเมื่อเปิด session
4. ถ้าเคยอัปโหลดไฟล์ zip ไว้ ให้ถอดตัวนั้นออกก่อน ไม่อย่างนั้น hook จะรันซ้ำสองครั้ง

## วิธีทำงาน (ทุกงานเดินแบบเดียวกัน)
คุณเป็นหัวหน้าที่สั่งงานและตัดสินใจ Claude ทำงานให้จบแล้วมารายงาน

1. **ค้นก่อนเริ่ม** — เอาชื่อ เลขที่เอกสาร ฟอร์ม และงวดในคำสั่ง ไปค้นในแผนที่เอกสาร แล้วค้นสดในโฟลเดอร์และกล่องเมล
   จะได้ไม่ต้องถามคุณว่าไฟล์อยู่ไหน
2. **อ่านก่อนทำ** — ข้อมูลบริษัท (`Accountant/company-facts.md`) บทเรียนของ skill นั้น (`Accountant/lessons/`)
   และความจำที่ตรงกับงาน (`Accountant/memory/`: ผู้ขายรายนี้ปฏิบัติอย่างไร เคยตัดสินใจอะไร ยอดยกมา)
3. **ถามครั้งเดียว** — ข้อมูลไม่ครบ (งวด เอกสาร deadline) จะรวมเป็นคำถามเดียว พร้อมคำตอบที่แนะนำ
4. **ลงมือตามขนาดงาน** — งานประจำวัน (เช็คเมล สแกนเอกสาร) ใช้โมเดลเร็วประหยัด งานประจำงวด
   (ปิดงวด ภาษี ปรับปรุง) ใช้โมเดลกลางและให้โมเดลใหญ่ตรวจ งานใหญ่ (ปิดงบปี ภ.ง.ด.50/51) ใช้โมเดลใหญ่
5. **ตรวจตัวเลข** — ทุกตัวเลขที่จะยื่น ส่ง หรือรายงาน ต้องผ่านการกระทบยอด (`reconcile-check`) ก่อน
   ไม่ผ่านแก้ 1 ครั้ง ยังไม่ผ่านก็รายงานตามจริง
6. **ผู้ตรวจอิสระดูอีกชั้น** — `auditor` ตรวจผลเทียบกับที่สั่ง โดยไม่เห็นว่าทำงานมาอย่างไร
7. **รายงาน 3 ส่วน** — **ผลลัพธ์** (1 บรรทัด + ลิงก์ไฟล์) · **หลักฐาน** (เช็คอะไรผ่านบ้าง) ·
   **ต้องให้คุณตัดสินใจ** (เรื่องที่ต้องกดยืนยัน พร้อมเหตุผล)
8. **จดบันทึกงาน** — เขียนลงสมุดบันทึกงานเสมอ แม้ไม่มีอะไรผิดพลาด แล้วบอกว่า "บันทึกงาน J-…"
9. **เก็บบทเรียน** — ถ้าคุณแก้งาน ตรวจไม่ผ่านแล้วแก้ หรือขั้นไหนพลาด จะจดบทเรียน 1 บรรทัดและบอกคุณ
   ถ้าไม่มีจะบอกว่า "ไม่มีบทเรียนใหม่" พร้อมเหตุผล

## Claude จะไม่ทำเองเด็ดขาด (ต้องให้คุณกดยืนยัน)
ยื่นภาษี / ประกันสังคม / DBD · ส่งอีเมลหรือไฟล์ออกไปข้างนอก · จ่ายเงิน · ลบหรือแก้ข้อมูลงวดที่ปิดแล้ว ·
เรื่องภาษีที่ตีความได้หลายทาง — ทุกข้อมาพร้อม "เหตุผล" และหลักฐานให้คุณตัดสิน
เงินเดือน เลขบัตรประชาชน เลขบัญชีธนาคาร และรหัสผ่าน ไม่ถูกบันทึกลงความจำหรือบทเรียนเด็ดขาด

## ความจำถาวร (`Accountant/memory/`)
ทุกอย่างเป็นไฟล์ข้อความธรรมดาในโฟลเดอร์งาน เปิดอ่านและแก้เองได้ ลบรายการไหนก็ได้ Claude เปิดสารบัญ
(`index.md`) ก่อนแล้วอ่านเฉพาะรายการที่ตรงกับงาน ไม่โหลดทั้งหมด

| ไฟล์ | เก็บอะไร |
|---|---|
| `index.md` | สารบัญ หนึ่งบรรทัดต่อหนึ่งรายการ |
| `parties.md` | ผู้ขาย / ลูกค้า / ผู้รับเงินแต่ละราย: หัก ณ ที่จ่ายเท่าไร VAT ไหม ลงบัญชีไหน พร้อมหลักฐาน |
| `decisions.md` | ข้อตัดสินใจและเหตุผล ใครอนุมัติ เมื่อไร มีผลถึงเมื่อไร |
| `recurring.md` | รายการประจำเดือนและช่วงยอดปกติ (ยอดผิดช่วง = ถามคุณ ไม่ลงบัญชีเงียบๆ) |
| `periods.md` | สถานะแต่ละงวด ฟอร์มที่ยื่น เลขอ้างอิง ยอดยกไปงวดหน้า วันที่สำรองข้อมูล |
| `sources.md` | แหล่งข้อมูลที่ใช้ซ้ำ: ไฟล์ ชีท ช่วงเซลล์ ผู้ส่งเมลและหัวข้อ จุดที่เคยมีปัญหา |
| `formulas.md` | สูตรและอัตราที่ใช้: สูตร อ้างอิงมาตราหรือคำวินิจฉัย ใช้ที่ไหน ตรวจล่าสุดเมื่อไร |
| `catalog.tsv` · `links.tsv` | **แผนที่เอกสาร** รายการเอกสารที่เคยอ่าน (ไฟล์ เมล ชื่อ เลขที่เอกสาร งวด) และเส้นเชื่อมระหว่างงาน เอกสาร ผู้ขาย สูตร งวด |
| `ledger/ปี-เดือน.md` | **สมุดบันทึกงาน** หนึ่งรายการต่อหนึ่งงาน เขียนทุกครั้งที่งานจบ ติดขัด หรือหยุด |

รายการหนึ่งในสมุดบันทึกงานหน้าตาแบบนี้ (ตัวอย่าง):
```
## J-20261031-2 16:40 payment-prep - ใบสำคัญจ่ายผู้ขายประจำเดือน
- client / period: บริษัทของเรา / 2026-10
- status: done
- read: S-2 (Payments\2026-10.xlsx / Sheet1 / A2:F80); email "ใบแจ้งหนี้ตุลาคม" from ผู้ขายระบบคลาวด์, 2026-10-29
- used: F-3 (หัก ณ ที่จ่าย = ฐาน x อัตรา); P-3
- made: Vouchers\PV-2026-10.xlsx / Sheet1 / A1:H24
- checks: reconcile-check pass; auditor pass; approved by <ผู้อนุมัติ> on 2026-10-31
- problems: ไฟล์ธนาคารใช้ปี พ.ศ. -> แปลงก่อนอ่าน (saved: lessons/payment-prep.md)
```
ถามย้อนได้ เช่น "ตัวเลขช่อง D14 ในใบสำคัญจ่ายเดือนนี้มาจากไหน", "ผู้ขายรายนี้เคยมีปัญหาอะไร", "ภ.พ.30 เดือนไหนทำเมื่อไร",
"สูตรหัก ณ ที่จ่ายใช้ที่ไหนบ้าง" Claude ค้นสมุดบันทึกงานแล้วตอบพร้อมเลขงานและเลขรายการ

**ความเป็นส่วนตัว:** ความจำเป็นของบริษัทนั้นเท่านั้น โหมดหลายลูกค้าแยกโฟลเดอร์ต่อลูกค้า
(`Accountant/memory/<ลูกค้า>/`) และห้ามเอาข้อมูลของรายหนึ่งไปใช้กับอีกราย เก็บหัวข้อเมลและชื่อไฟล์เพื่อให้ค้นเจอ
แต่ไม่เก็บเนื้อเมลหรือเนื้อหาเอกสาร ความจำไม่เคยสูงกว่าเอกสารต้นฉบับ กฎหมาย หรือคำสั่งล่าสุดของคุณ

## ค้นหาและแผนที่งาน (`accountant-graph`)
เหมือนการค้นโค้ดด้วยกราฟ แต่สิ่งที่ค้นคือของสำนักงานบัญชี: **ชื่อผู้ขาย/ลูกค้า เลขที่เอกสาร ฟอร์ม บัญชี งวด**
ในไฟล์ PDF อีเมล Word Excel CSV และโน้ต เป็นไฟล์ข้อความธรรมดา ไม่ต้องติดตั้งโปรแกรมเพิ่ม
- **ค้นก่อนเริ่มทุกงาน** — ค้นแผนที่เอกสารก่อน ถ้าไม่เจอค้นสดในโฟลเดอร์งาน ที่เก็บไฟล์ และกล่องเมลตามลำดับ
  แสดงตัวเลือกไม่เกิน 5 รายการให้คุณยืนยัน ไฟล์สแกนที่อ่านไม่ได้จะบอกตรงๆ ไม่เดา
- **ชื่อเดียวกันหลายแบบ** — ชื่อภาษาไทย อังกฤษ และชื่อย่อของผู้ขายรายเดียวกันจดไว้ครั้งเดียว (`aka:`) ค้นด้วยชื่อไหนก็เจอ
  และตัดคำ บริษัท / บจก. / จำกัด / Co., Ltd. ออกก่อนเทียบ
- **จดทุกเอกสารที่ใช้** — ทุกงานลงทะเบียนเอกสารและอีเมลที่อ่าน (ชื่อเรื่อง ที่อยู่ งวด ชื่อ เลขที่เอกสาร ไม่เก็บเนื้อหาและยอดเงิน)
- **ทำดัชนีย้อนหลัง** — พิมพ์ "ทำดัชนีเอกสาร" ให้อ่านโฟลเดอร์หรือกล่องเมลทีละเดือนจากเก่าไปใหม่ หยุดเมื่อไรก็ได้
- **ถามความเชื่อมโยง** — ทุกอย่างที่เกี่ยวกับผู้ขายรายหนึ่ง, สืบย้อนตัวเลขถึงเอกสารและเมลต้นทาง, ถ้าเปลี่ยนสูตรหรืออัตรานี้กระทบงานและงวดไหน,
  สองสิ่งนี้เชื่อมกันอย่างไร
- **แผนที่งาน** — "ขอดูแผนที่งาน" สร้างหน้าภาพกราฟของผู้ขายหนึ่งราย หรือหนึ่งงวด กดดูสิ่งที่เชื่อมกัน (ครั้งละไม่เกิน ~300 เส้น)
- **ตรวจตอนปิดงวด** — เจอรหัสที่อ้างแต่ไม่มีอยู่จริง เอกสารที่ไม่มีงานไหนเคยอ่าน หรือผู้ขายที่น่าจะซ้ำกัน จะรายงานเป็นรายการค้าง ไม่แก้เงียบๆ

### เครื่องมือที่ Claude เรียกใช้ได้ (Python)
การค้นหา ใส่เลขรหัส เขียนสมุดบันทึกงาน และตรวจความครบ ทำโดยสคริปต์ Python (ใช้ไลบรารีมาตรฐานอย่างเดียว ไม่ต้องติดตั้งอะไรเพิ่ม)
เพื่อให้ผลแม่นและซ้ำได้ ไม่ต้องพึ่งการที่ Claude นับหรือพิมพ์เอง Claude เรียกได้ 3 ทางตามลำดับ:
1. **เครื่องมือ MCP** (plugin เปิดให้เองเมื่อเครื่องมี Python): `accountant_find`, `accountant_trace`, `accountant_impact`,
   `accountant_path`, `accountant_neighbors`, `accountant_job` (เขียนสมุดบันทึกงาน + แคตตาล็อก + เส้นเชื่อมในคำสั่งเดียว),
   `accountant_register_doc`, `accountant_party`, `accountant_lesson`, `accountant_index_scan`, `accountant_usage`,
   `accountant_problems`, `accountant_check`, `accountant_map`, `accountant_init`
2. **คำสั่งในเทอร์มินัล** เมื่อมี shell: `python3 skills/accountant-graph/scripts/graph.py --root <โฟลเดอร์งาน> find ...`
3. **ทำมือตามขั้นตอนใน skill** เมื่อไม่มี Python (ใช้ได้เหมือนเดิม แต่ความแม่นขึ้นกับ Claude)

ที่เครื่องมือทำให้: ค้นด้วยชื่อใดก็ได้ของผู้ขายรายเดียวกัน (ไทย/อังกฤษ/ย่อ) ทั้งในแคตตาล็อก ความจำ และ**ไฟล์สดในโฟลเดอร์**
(อ่านข้อความใน md, txt, csv, tsv, html, docx, xlsx ส่วน PDF และรูปค้นได้แค่ชื่อไฟล์ เนื้อหาต้องให้ `doc-reader` อ่าน)
ทำดัชนีทีละเดือน สืบย้อนตัวเลขถึงไฟล์ ชีท ช่วงเซลล์ และหัวข้อเมลต้นทาง วิเคราะห์ผลกระทบของสูตรหรืออัตรา
หาเส้นทางระหว่างสองสิ่ง วาดแผนที่เป็นไฟล์ `map.html` เปิดในเบราว์เซอร์ได้เลย และตรวจความครบ (รหัสที่อ้างแต่ไม่มี
เอกสารที่ไม่มีงานอ่าน ผู้ขายซ้ำ) เครื่องมือปฏิเสธการบันทึกเลข 13 หลักที่อาจเป็นเลขบัตรประชาชนหรือเลขผู้เสียภาษี

**บังคับด้วย hook:** ก่อนหยุดทำงาน สคริปต์ตรวจว่างานที่รายงานผล (ผลลัพธ์ / หลักฐาน) ได้เขียนสมุดบันทึกงานแล้วหรือยัง
ถ้ายังจะกันไว้ 1 ครั้งและบอกให้เรียก `accountant_job` (ข้ามเมื่อไม่ใช่โฟลเดอร์งานบัญชี ไม่วนซ้ำ และปล่อยผ่านเมื่อไม่มี Python)
ส่วนการจดบทเรียนเมื่อคุณแก้งานยังตรวจด้วย prompt hook เดิม

## เก่งขึ้นเองยังไง
- **ทุก skill เหมือนกัน** — ท้ายทุก skill มีขั้น "Learn and remember": ก่อนทำอ่านบทเรียนและความจำ ระหว่างทำจดสิ่งที่ใช้
  และปัญหา หลังทำเขียนสมุดบันทึกงานและจดบทเรียนถ้ามีสัญญาณ
- **บทเรียน** — เมื่อคุณแก้งาน ("ไม่ใช่แบบนี้", "ยาวไป", "ตัวเลขผิด") หรือการตรวจไม่ผ่านแล้วแก้ Claude จดบทเรียน
  หนึ่งบรรทัดลง `Accountant/lessons/<ชื่อ skill>.md` แล้วบอกคุณ (ลบได้เสมอ) บทเรียนไม่มีข้อมูลลูกค้า มีแต่ "วิธีทำ"
  จดเฉพาะที่ยืนยันแล้ว ถ้าบทเรียนเก่าทำให้พลาดจะแก้หรือลบ ไม่วางซ้อนกัน
- **ทบทวนประจำสัปดาห์** — Claude อ่านสมุดบันทึกงาน นับว่าแต่ละ skill ใช้ครั้งล่าสุดเมื่อไรและกี่ครั้ง หาปัญหาเดียวกันที่เกิดซ้ำ
  แล้วเสนอ: รวมหรือลบบทเรียน เพิ่มบทเรียน ปรับสูตรหรือแหล่งข้อมูลที่เปลี่ยน พร้อมหลักฐาน คุณเป็นคนอนุมัติ
- **แก้ skill ได้ทันที** — `accountant_lesson` บันทึกบทเรียน 1 ประโยค (ปฏิเสธอีเมลและเลข 13 หลัก ไม่บันทึกซ้ำ จำกัด 40 ข้อต่อ skill) ทุก skill อ่านก่อนงานถัดไป จึงมีผลทันที
- **ยกเข้า skill** — บทเรียนที่ใช้ทุกครั้งจะถูกเสนอให้รวมเข้าตัว skill: หลังคุณอนุมัติ คำสั่ง `graph.py promote <skill> --plugin <โฟลเดอร์ plugin> --yes` จะเติมหัวข้อ "Learned rules" ใน `SKILL.md` เพิ่มเลขเวอร์ชัน และเก็บบทเรียนเดิมเข้าคลัง (ไม่ใส่ `--yes` จะแสดงตัวอย่างเฉยๆ) แล้ว build และติดตั้ง plugin ใหม่
- **skill ใหม่** — ถ้างานชนิดเดียวกันเกิดขึ้น 3 ครั้งขึ้นไปโดยไม่มี skill รองรับ จะร่างข้อเสนอ skill ใหม่ให้คุณอนุมัติ
- **ตัวเตือน (hook)** — ก่อนหยุดทำงาน ถ้างานจบแล้วยังไม่ได้เขียนสมุดบันทึกงาน หรือคุณแก้งานแล้วยังไม่ได้จดบทเรียน
  ระบบเตือนให้ทำก่อน (เตือนครั้งเดียวไม่วนซ้ำ) ถ้าไม่ขึ้นเตือน การจดยังอยู่ในขั้นปิดงานของ `accountant-chief` และท้ายทุก skill

### ทดสอบก่อนใช้งานจริง (สำหรับคนที่ลองใช้ก่อน)
ใช้โฟลเดอร์ทดลองที่ไม่มีข้อมูลจริง (เช่น `Accounting-ทดลอง`) วางไฟล์ `invoice.txt` ที่มีข้อความ
`ใบแจ้งหนี้ CloudHost ตุลาคม INV-0042` แล้วพิมพ์ตามลำดับ ดูว่า "ควรเห็น" ตรงไหม

| # | พิมพ์ | ควรเห็น |
|---|---|---|
| 1 | `เริ่มงาน` | ถามข้อมูลบริษัทเป็นข้อความเดียว แล้วสร้างโฟลเดอร์ `Accountant/` (มี `company-facts.md`, `register.xlsx`, `lessons/`, `memory/`) |
| 2 | `เพิ่มผู้ขายชื่อ บริษัท คลาวด์โฮสต์ จำกัด ชื่ออังกฤษ CloudHost Co., Ltd.` | ได้รหัส `P-1` และมีรายการใน `Accountant/memory/parties.md` พร้อมบรรทัด `aka:` |
| 3 | `ทำดัชนีเอกสารของโฟลเดอร์นี้` | `indexed … new file(s)` และมี `K-1` ใน `memory/catalog.tsv` |
| 4 | `หาเอกสารของ คลาวด์โฮสต์` | เจอ `invoice.txt` และ `P-1` ทั้งที่ไฟล์เขียนว่า CloudHost (ชื่อไทยกับอังกฤษต้องเจอกัน) |
| 5 | `อ่านเอกสาร invoice.txt แล้วสรุปให้ เป็นงานทดลอง อย่ายื่นหรือจ่ายจริง` | รายงาน 3 ส่วน (ผลลัพธ์ / หลักฐาน / ต้องให้คุณตัดสินใจ) แล้วบอก `บันทึกงาน J-…` และมีไฟล์ `memory/ledger/ปี-เดือน.md` |
| 6 | `ตัวเลขนี้มาจากไหน: invoice.txt` | บอกงาน `J-…` ไฟล์ ชีท ช่วงเซลล์ ผลตรวจ |
| 7 | `ไม่ใช่แบบนี้ ที่นี่ปัดเป็นทศนิยม 2 ตำแหน่ง` | บอกว่าบันทึกบทเรียนอะไร และมีไฟล์ใน `Accountant/lessons/` |
| 8 | `ตรวจความครบของความจำ` | `memory is consistent` หรือรายการที่ขาด |
| 9 | `ขอดูแผนที่งาน` | ได้ไฟล์ `memory/map.html` เปิดในเบราว์เซอร์ได้ |
| 10 | `จำเลขผู้เสียภาษี 0105536012345 ของผู้ขายไว้` | ต้อง**ปฏิเสธ** (ห้ามเก็บเลข 13 หลัก) |

ถามเพิ่มได้ว่า `คุณมีเครื่องมือชื่อ accountant_ อะไรบ้าง` ควรเห็น 15 ตัว (`accountant_find`, `accountant_job` ฯลฯ)
ถ้าไม่เห็น แปลว่าเครื่องไม่มี Python หรือ MCP ไม่เริ่ม ระบบยังทำงานได้แบบทำมือ แต่ช่วยแจ้งผู้ดูแลด้วย

**ส่งผลกลับ:** ข้อไหนไม่ผ่าน ข้อความที่เห็นจริง และภาพโฟลเดอร์ `Accountant/memory/` (ขอแค่ชื่อไฟล์ ไม่ต้องส่งเนื้อหาจริง)

**ทดสอบเครื่องมือจากเทอร์มินัล (ต้องมี Python 3.8 ขึ้นไป):** แตกไฟล์ `.plugin` (เป็นไฟล์ zip เปลี่ยนนามสกุลเป็น `.zip` แล้วแตก)
เข้าโฟลเดอร์ที่แตก แล้วรัน (macOS/Linux; บน Windows ใช้ `py -3` แทน `python3`):
```
python3 --version
acc() { python3 -B skills/accountant-graph/scripts/graph.py --root "$HOME/ทดสอบ-บัญชี" "$@"; }
mkdir -p "$HOME/ทดสอบ-บัญชี/Docs"
echo "ใบแจ้งหนี้ CloudHost ตุลาคม INV-0042" > "$HOME/ทดสอบ-บัญชี/Docs/invoice-2569-10.txt"
acc init
acc party --name "บริษัท คลาวด์โฮสต์ จำกัด" --aka "CloudHost Co., Ltd." "คลาวด์โฮสต์"      # ควรได้ P-1
acc index-scan "$HOME/ทดสอบ-บัญชี/Docs"                                                  # indexed 1 new file(s)
acc find "คลาวด์โฮสต์" --files "$HOME/ทดสอบ-บัญชี/Docs"                                  # เจอ K-1, P-1 และไฟล์
echo '{"skill":"payment-prep","summary":"ทดสอบ","period":"2026-10","read":[{"id":"K-1","supplied":"ยอดค้างจ่าย"}],"used":["P-1"],"made":["Vouchers/PV.xlsx!A1:H5"],"checks":"reconcile-check pass"}' | acc job -   # บันทึกงาน J-…-1
acc trace K-1
acc check                                                                                  # memory is consistent
acc lesson payment-prep "แปลงปี พ.ศ. ก่อนอ่านไฟล์ธนาคาร"                                  # lesson saved …
acc map --period 2026-10                                                                   # map written to …/map.html
acc lesson payment-prep "ติดต่อ a@b.com"                                                   # error: refused (e-mail) และ exit 2
```
ผู้ดูแล plugin ที่มี repo ทั้งชุด รันชุดทดสอบอัตโนมัติได้ด้วย `python3 -m unittest discover -s tests -v` (35 ข้อ)

### ใช้บน Windows
- ติดตั้ง plugin โดยเปิดไฟล์ `.plugin` ใน Claude Desktop สำหรับ Windows
- โฟลเดอร์งานแนะนำเป็นโฟลเดอร์ใน OneDrive หรือ Google Drive for desktop ที่ path สั้นๆ เช่น
  `C:\Users\<ชื่อ>\OneDrive\Accounting` (Windows มีปัญหากับ path ยาวเกิน ~250 ตัวอักษร)
- Excel ที่ตั้งภาษาไทยอาจแสดงปีเป็น พ.ศ. — Claude ตรวจและแปลงให้ ไฟล์ CSV บันทึกแบบที่ Excel อ่านภาษาไทยได้

- โครง: `.claude-plugin/plugin.json`, `skills/*/SKILL.md` (เนื้อหาอังกฤษ ตัวกระตุ้นภาษาไทย), `agents/`, `hooks/hooks.json`,
  `CONNECTORS.md`, `companies/_template/` (ชั้นกฎเฉพาะบริษัท ใช้เมื่อฐานยังไม่พอ)
- ทดสอบเครื่องมือ: `python3 -m unittest discover -s tests -v` (`build.sh` คอมไพล์สคริปต์และรันทดสอบให้เองเมื่อมี Python และล้มเมื่อไม่ผ่าน)
- สร้างไฟล์ plugin: `bash scripts/build.sh` (Windows: `powershell -ExecutionPolicy Bypass -File scripts\build.ps1`)
  ได้ `dist/thai-accounting-office.plugin` และ `.zip` — ตัวสร้างล้มเหลวถ้า description ใน SKILL.md มี `<` หรือ `>`
  (Claude Desktop ปฏิเสธ) หรือถ้าเวอร์ชันของ `work-folder-CLAUDE.md` ไม่ตรงกับที่ฝังใน `คู่มือการใช้งาน.html`
- skill ใหม่: ใส่ท้ายไฟล์ด้วยบล็อก `## Learn and remember (every job)` เหมือน skill อื่น
- ปล่อยเวอร์ชันใหม่: นำบทเรียนที่ใช้ทุกครั้งเข้า `SKILL.md` เพิ่มเลขเวอร์ชันของ skill และของ plugin แล้ว build
  ผู้ใช้ลบ plugin เก่าและอัปโหลดตัวใหม่ (ข้อมูลใน `Accountant/` ไม่หาย)
- ห้ามใส่ข้อมูลลูกค้าหรือบริษัทลงใน repo นี้

## ข้อควรรู้
- ตัวเลขภาษีและกำหนดยื่นใน skill เป็นค่าตั้งต้น — ตรวจประกาศกรมสรรพากรปีปัจจุบันก่อนยื่นจริงเสมอ
- Claude ช่วยเตรียมงาน ความรับผิดชอบทางวิชาชีพยังเป็นของผู้ทำบัญชีและผู้สอบบัญชี
- สมุดบันทึกงานและความจำเขียนโดย Claude ตามคำสั่งใน skill และมี hook เตือน แต่ไม่มีอะไรบังคับได้ 100%
  ถ้าเห็นว่างานไหนไม่ถูกบันทึก พิมพ์ "บันทึกงานนี้ลงความจำ" ได้เลย และตรวจสมุดบันทึกเป็นระยะ
- ข้อมูลของแผนที่เป็นไฟล์ข้อความ (`.tsv` และ `.md`) ไม่ใช่ฐานข้อมูล เปิดดูและแก้ใน Excel ได้ และส่งต่อเครื่องมือกราฟตัวอื่นได้ เครื่องมือ Python จำเป็นต้องมี Python ในเครื่อง (ถ้าไม่มี ระบบทำงานแบบทำมือตามขั้นตอนใน skill) บน Windows ที่ใช้ `py` แทน `python3` hook และ MCP อาจไม่เริ่ม ซึ่งยังไม่ได้ทดสอบ
- ระบบความจำ แผนที่ และสมุดบันทึกงานยังใหม่ ยังไม่เคยใช้กับงานจริงในโฟลเดอร์ทำงานจริง ควรลองกับงานเล็กก่อน
